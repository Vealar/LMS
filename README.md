# LMS для поддержки учебного процесса

Проект выполнен в рамках производственной практики в Научно-учебной лаборатории облачных и мобильных технологий ФКН НИУ ВШЭ.

Ниже приведено краткое описание проекта. Более подробное описание разработки, принятых решений и реализованной функциональности находится в отчёте по производственной практике.

## Цель проекта

Целью работы была разработка веб-приложения для поддержки учебного процесса, рассчитанного на две основные категории пользователей — студентов и преподавателей.

Система должна была объединить работу с учебными материалами, заданиями и тестами в одном приложении.

Студенту необходимо было предоставить возможность:

- просматривать структуру курса и учебные материалы;
- сдавать задания;
- проходить тесты;
- получать результаты.

Преподавателю:

- создавать и изменять структуру курса;
- публиковать учебные материалы;
- создавать задания и тесты;
- проверять работы студентов.

## Условия разработки

Проект разрабатывался **индивидуально** в ограниченные сроки производственной практики — с **1 по 14 июля 2025 года**.

За это время необходимо было:

- спроектировать приложение;
- определить модель данных;

Использование **React** было задано в требованиях к клиентской части проекта.

## Архитектура

Приложение построено по клиент-серверной архитектуре.

### Клиентская часть

Клиент реализован на **React** и взаимодействует с сервером через REST API.

Используются:

- **React Router** — для навигации;
- **React Query** — для работы с серверными данными и их синхронизации с состоянием клиента;
- **Axios** — для HTTP-запросов.

### Серверная часть

Сервер реализован на **Node.js** и **Express**.

Обработка запросов разделена между:

- маршрутизацией;
- контроллерами;
- сервисным слоем.

Для хранения структурированных данных используется **PostgreSQL**, доступ к базе данных организован через **Prisma ORM**.

### Работа с файлами

Учебные материалы и работы студентов хранятся отдельно от основной базы данных в **MinIO**.

В PostgreSQL сохраняются сведения о файлах и связи с объектами системы, а сами файлы размещаются в объектном хранилище.

PostgreSQL и MinIO запускаются в Docker-контейнерах.

## Основные решения

### Разделение функциональности

Серверные маршруты разделены по основным областям системы:

- аутентификация;
- курсы;
- учебные материалы;
- задания;
- тесты;
- файлы.

Проверка прав доступа выполняется до передачи запроса прикладной логике.

### Структура курса

Для курса была разработана единая модель учебных блоков четырёх типов:

- **Теория** — текстовые материалы и прикреплённые файлы;
- **Файл** — отдельный загружаемый материал;
- **Задание** — описание, дедлайн, вложения и возможность отправить решение;
- **Тест** — вопросы с одним или несколькими вариантами ответа, ограничением числа попыток и времени прохождения, а также автоматическим подсчётом результата.

Для преподавателя реализован отдельный режим редактирования. В нём можно создавать и изменять темы курса и отдельные блоки, управлять заданиями и тестами и проверять работы студентов.

### Аутентификация и роли

Аутентификация построена на **JWT**.

В системе предусмотрены роли студента и преподавателя, для которых разграничены доступные действия.

Для серверной части также реализован общий механизм обработки ошибок и формирования ответов API.

## Результат

В результате был разработан рабочий прототип LMS с клиентской и серверной частями, базой данных и отдельным файловым хранилищем.

Реализованы:

- регистрация и авторизация;
- роли студента и преподавателя;
- структура учебного курса;
- загрузка и просмотр материалов;
- создание и сдача заданий;
- тестирование с автоматическим подсчётом результата;
- редактирование курса преподавателем;
- проверка работ студентов;
- загрузка и хранение файлов.

Проект не ставил целью разработку принципиально нового подхода к построению LMS. Основной результат работы — самостоятельное проектирование и реализация законченной клиент-серверной системы по заданным требованиям, включая выбор архитектуры, технологий и реализацию основных пользовательских сценариев.

# LMS — запуск проекта

## Требования перед запуском

Перед запуском убедитесь, что установлены следующие компоненты:

- **Node.js** : https://nodejs.org/
- **npm** (подтягивается вместе с Node.js)
- **Docker + Docker Compose**: https://www.docker.com/products/docker-desktop/

> После установки **перезагрузите компьютер**, чтобы переменные окружения применились корректно.

---

## Подготвка окружения

### 1. Клонировать репозиторий

```bash
git clone https://github.com/Vealar/LMS.git
cd LMS
```

### 2. Настройка backend
1) Перейдите в папку серверной части:
```bash
cd backend
```

2) Создайте .env файл в папке backend, пример содрежимого:
    DATABASE_URL="postgresql://lms_user:lms_pass@localhost:5433/lms_db?schema=public"  
    (//возможно prisma будет выдавать ошибку подключения на Windows, поменяйте localhost -> 127.0.0.1)
    
    JWT_SECRET="PaM_Pam_PAM_PAM"
    
    PORT=8080
    
    S3_ENDPOINT=http://localhost:9000
    S3_ACCESS_KEY=minioadmin
    S3_SECRET_KEY=minioadmin
    S3_BUCKET=lms-files
    S3_REGION=us-east-1
4) Установите зависимости 
```bash
npm install           
```
4) Подключить prisma
```bash
npx prisma generate
npx prisma migrate deploy
```
### 3. Настройка frontend
Перейдите в папку клиентской части:
```bash
cd frontend
```
```bash
npm install            # Установка зависимостей
```

---

## Запуск приложения
Находясь в корне проекта поднимите базы данных(должен быть включен Docker):
```bash
docker compose up
```
Затем запустите сервер:
```bash
cd backend
npm run dev
```

Затем запустите клиент:
```bash
cd frontend
npm run dev
```
